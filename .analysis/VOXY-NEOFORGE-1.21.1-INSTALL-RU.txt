0. ГЛАВНОЕ, ЧТО НАДО ЗНАТЬ
=========================================================
Официального Voxy под Minecraft 1.21.1 НЕ СУЩЕСТВУЕТ - ни на Fabric, ни на NeoForge.

Проверено:
- Modrinth API, проект voxy (id fxxUqruK, автор cortex/MCRcortex):
  запрос версий с фильтром game_versions=["1.21.1"] вернул пустой массив [].

- Поддерживаемые версии Voxy: 1.20.4, 1.21.6, 1.21.7, 1.21.8, 1.21.9, 1.21.10,
  1.21.11, 26.1, 26.1.1, 26.1.2, 26.2, 26.3. Версии 1.21.1 в списке нет.
- На CurseForge Voxy не выложен (страница mc-mods/voxy отдаёт 404).
- В README NeoForge-порта прямо сказано: автор оригинала бэкпортировать на 1.21.1 не будет.

Значит для связки NeoForge 1.21.1 + PureScale Modern есть три пути. Ниже все три.

  minecraft_version=1.21.1

ДВЕ ОГОВОРКИ ИМЕННО ДЛЯ ВАШЕЙ СВЯЗКИ
1. В changelog PureScale 1.3.0 в разделе "Known issues" прямо написано:
   "Distant Horizons flicker, invisible name tags and the integrated-GPU artifacts
    are on my list but not fixed in this release."
   То есть мерцание DH при работающем PureScale автор признаёт и в 1.3.0 НЕ починил.

Как уменьшить мерцание: в DH 3.3.0+ добавлен Temporal Antialiasing
("Add Temporal Antialiasing to fix flicking/noise in distant terrain") - включите его.
И на время проверки держите Frame Gen выключенным (см. предыдущий разбор зависания).

компиляции, миксины не зарегистрированы) -> LOD рисуется вне конвейера шейдер-пака.
Открытые issues порта: #5 (автор пробовал Photon/Eclipse/Helian), #6. Сам Eclipse Voxy
поддерживает, так что дело не в паке.
Решение: сборка PR #45 (закрыт, не влит) = voxy 0.2.15-beta, compileOnly против
Sodium NeoForge 0.8.13 и Iris NeoForge 1.8.14-beta.1, все 11 iris-миксинов активны.
Важно для повторной сборки: PR #45 ждёт в gitignored libs/ три jar'а
  libs/sodium-neoforge-0.8.12-beta.2-mod.jar
  libs/iris-neoforge-1.8.14-beta.1.jar

=== ПОДЛАГИВАНИЯ С VOXY (лог latest-2.log, 06.11.2026) ===
Сборка 0.2.15-beta встала, Iris-конвейер работает: "Creating voxy iris render pipeline",
pipeline 'IrisVoxyRenderPipeline', renderer 'MDICSectionRenderer',
"IrisShaderPatch: External opaque/translucent shader patch applied".
Главная причина лагов - ОДНОВРЕМЕННО стоят два LOD-мода:
  DistantHorizons-3.3.3-1.21.1-fabric-neoforge.jar + voxy-0.2.15-beta.jar
Iris при этом биндится к DH ("Queuing DH event binding", "DH Ready, binding Iris event
handlers"), а Voxy отдельно патчит те же шейдеры. DH вешает серверные миксины
MixinChunkGenerator/MixinChunkMap и генерит фейковые чанки на серверном потоке.
Лаг в логе - серверный, не рендерный:
  [ipl-server-watchdog/ERROR] SERVER THREAD STALLED ~11s (state=TIMED_WAITING)
  3x "Can't keep up! Is the server overloaded? Running 8629ms / 172 ticks behind"
Стек ста́лла: BlockableEventLoop.managedBlock <- ServerChunkCache.getChunk <-
Level.getBlockState <- teallib VariantHolderBlockEntity.sync (блокирующая догрузка чанка).
Вторая проблема: Immersive Portals x Sable 0.5.0 официально несовместим с Voxy
(сообщение в чате, iPortalTeam/ImmersivePortalsMod#1524) - "удалите один из двух модов".
Конфиг Voxy: config/voxy-config.json (FMLPaths.CONFIGDIR + "voxy-config.json"),
gson LOWER_CASE_WITH_UNDERSCORES. Поля и дефолты (VoxyConfig.java, PR #45):
  enabled=true, enable_rendering=true, ingest_enabled=true,
  section_render_distance=16  (LOD = 16 * sub_division_size 64 = 1024 блока),
  service_threads=coreCount/1.5 (на 8C/16T ~ 10; в логе пул 5, у второго инстанса 1),
  sub_division_size=64, sky_fog_distance=96, fog_intensity=1.0, fog_density=0.0,
  adapt_cloud_distance=true, cloud_distance=0,
  dont_use_sodium_builder_threads=false, ssao_mode=null(=AUTO)
Что крутить при лагах: section_render_distance 16->8; service_threads 10->6;
dont_use_sodium_builder_threads=true; ssao_mode="disabled".
VRAM: Voxy держит sparse-буфер геометрии 4 294 966 272 байт (NVIDIA workaround
"sparse buffer allocation"), свободной VRAM было 8731 Мб -> 8236 Мб.
Полёт над новой местностью дорогой по определению: в логе ChunkBoundRenderer растёт
6144 -> 9216 -> 13824 -> 20736 -> 31104 ровно в окнах фризов (инджест новых секций).
Железо: Ryzen 7 5700X (16 потоков), RTX 5080 (616.92), Win11, Java 21.0.7 Microsoft,
шейдерпак Eclipse-Shader-Unstable.zip (+ Bliss 2.1.1/2.1.2 в паке), ~200 модов.

=== ШЕЙДЕРЫ ВЫКЛЮЧАЮТСЯ ПРИ СОЗДАНИИ ПОРТАЛА (Immersive Portals) ===
Лог latest-3.log, цепочка:
  iPortal "Portal Generation Attempted" -> BlockManipulationClient.updateTargetedBlockThroughPortal
  -> ClientWorldLoader.getWorld -> createSecondaryClientWorld -> LevelRenderer.setLevel
  -> LevelRenderer.allChanged -> voxy mixin reloadVoxyRenderer -> VoxyRenderSystem.<init>
  -> RenderPipelineFactory.createIrisPipeline -> new IrisVoxyRenderPipeline
  -> ERROR "java.lang.IllegalStateException: Pipeline data already bound" (IrisVoxyRenderPipeline.java:39)
  -> catch в RenderPipelineFactory вызывает IrisUtil.disableIrisShaders()
     = IrisApi.getInstance().getConfig().setShadersEnabledAndApply(false)
  -> Iris: "Destroying pipeline ..." и "Shaders are disabled because enableShaders is set
     to false in iris.properties" (3 раза за сессию; также при повторном включении шейдеров
     из GUI: ShaderPackScreen.applyChanges -> setShadersEnabledAndApply -> Iris.reload ->
     IP _onWorldRendererReloaded -> withSwitchedWorld -> allChanged -> та же ошибка).
Суть: у Iris один IrisRenderingPipeline на измерение, у Voxy один слот
IrisVoxyRenderPipelineData.thePipeline; при переключении миров IP текущий pipeline Iris
принадлежит другому измерению и уже занят живым VoxyRenderSystem -> Voxy бросает
исключение и ГЛОБАЛЬНО гасит шейдеры (записывает enableShaders=false в config/iris.properties).
Патч (применяется в CI перед сборкой, коммит 1740183):
1) RenderPipelineFactory.createIrisPipeline: если pipeData.thePipeline != null - не создавать
   Iris-конвейер для этого инстанса, вернуть null (откат на NormalRenderPipeline), БЕЗ вызова
   IrisUtil.disableIrisShaders(); catch Throwable + pipeData.thePipeline = null (снять
   полу-привязку, если конструктор упал посередине).
2) IrisVoxyRenderPipeline.free(): убрать throw IllegalStateException при чужой привязке,
   добавить флаг voxyIrisPipelineFreed (идемпотентность, защита от "double freed" в
   TrackedObject.free0), очищать thePipeline только если он наш - GL-объекты старого
   конвейера по-прежнему освобождаются его VoxyRenderSystem.

1. normal (IrisPortalRenderer) — /imm_ptl_client_debug render_mode_normal
   14:55:22 OpenGL Error 1281 (GL_INVALID_VALUE) в IPIrisHelper/CHelper.doCheckGlError,
   затем чат "[Immersive Portals]Switched to compatibility portal rendering mode."
   -> IP сам откатывается в compatibility через 1-3 секунды.
2. experimental (ExperimentalIrisPortalRenderer) — 14:55:48
   шквал GL_INVALID_OPERATION (id=1282), по словам пользователя "ломает всё".
3. compatibility (IrisCompatibilityPortalRenderer) — режим по умолчанию
   IPIrisHelper.newCopyDepthStencil/copyColor = GL43C.glCopyImageSubData КАЖДЫЙ КАДР;
   4985 ошибок "source and destination internal formats are not compatible"
   (1035 только в этом логе). Копирование не происходит ->
   a) портал композитится без настоящей глубины => виден сквозь стены;
   b) кадр возвращается в финальный проход Iris с битыми вложениями => пропадает свет.

Причина: glCopyImageSubData требует СОВПАДЕНИЯ внутренних форматов текстур.
Iris (шейдерпак Eclipse) подменяет вложения главного фреймбуфера своими
(colortex/depth других форматов), поэтому копирования IP всегда падают.
К Voxy это отношения не имеет (ошибки сохранялись при enable_rendering=false).
