# Build 250: источники и пределы проверки

Мост использует локальный EMF, не копируя FA или TnM. EMF 3.3.9 `EMFModelPartRoot` вызывает onAnimationStart → собственный `EMFAnimationHandler.animate` → onAnimationEnd; TnM 1.0.4 добавляет движения из своего onAnimationEnd. Повторного ручного `applyAll` в 250 нет. Риг игрока wide/slim запекается отдельно и не устанавливается на общий renderer. На reloading общий renderer меняет якорь кэша. Трансформации шести частей переносятся как V * inverse(Vrest) * IvyRest, потом вычисляются вложенные локальные матрицы; при shear/NaN, движении root и т. п. отказ.

`EMFAnimationApi.animateModelForState` намеренно не применяется: ETF 7.2.4 не добавляет в стек повторно тот же state, но `unMount` снимает верх; игрок уже находится в caller-owned state. Анимация запускается из текущего state, временно выставляются фазы и приватный уникальный `entityRenderCount`, затем счётчик и четыре вычисляемых входа state восстанавливаются. Схема выбирает variant по локальному кешу изолированного рига, не записывая `lastModelSuffixOfEntity` менеджера. Внешние render-hooks могут иметь неизвестные побочные эффекты; полноценного многопользовательского теста нет.

Сигнатура требует marker из a_player_variables.jpm, реальные gait-подобные выражения var.mvmnt_[rl]legrx, связь их с каналами ноги и 36 каналов шести ванильных частей, направленных в те же ModelPart, которые отдаёт PlayerModel. Marker ОТСУТСТВУЕТ в основном player.jem как animKey, но присутствует в подключённом a_player_variables.jpm. Подобная сигнатура может быть скопирована и не доказывает происхождение пака. Официальный пользовательский ZIP FA не проверен. Стороннее зеркало FA 1.0 позволяет проверить содержимое выражений, но не официальную неизменность; недостающий player_face.jpm для анализа был пустой тестовой заглушкой. В модифицированном ParCool player.jem var marker тоже находится в соседнем a_player_variables.jpm; совместимость с полным стеком этого модпака не доказана.

Проверка байткода проводилась на внешних EMF 3.3.12 и ETF 7.2.6; исполнялся реальный root EMF 3.3.12 и хук TnM 1.0.4, а игровой API и провайдеры были подменены. Исходники файлов EMFModelPartRoot.java, EMFAnimationApi.java, EMFAnimationHandler.java tag v3.3.9 и v3.3.12 совпадают побайтно; это НЕ замена бинарного или игрового теста EMF 3.3.9. Визуал, actual EMF parser и реальные FA-формулы в игре не запускались.
