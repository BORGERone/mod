## Реализация

- Две команды выбираются независимо внутри обычных графовых узлов «Триггер»: начало преследования по точному `NpcProfile.identifier` либо нику игрока, и остановка для NPC-исполнителя. Сериализация графа и форматы существующих соединений не менялись.
- Команды проходят через два контекста существующей системы действий: `NpcActions.runSingle` (действие с игроком) и `runForEntity` (событие от сущности).
- AI hook подключён к `NpcAutoAiEngine255.runMobilityAndAutoAi`; преследование приоритетнее автономной прогулки/боя. Навигация запрашивает обновление цели раз в 10 тиков, поиск сущности группируется кэшом на 20 тиков.
- Строй шириной три позиции, сортировка активных преследователей по UUID; первая линия на расстоянии 1,4 блока вперёд, боковой интервал 1,4 блока, последующие линии с шагом 1,5 блока. Геометрия поворачивается по yaw цели.
- Активный target type/value записывается через существующий `NpcAutoAiEngine255.saveNpcData/loadNpcData` hook в NBT сущности. Недоступная/незагруженная цель не сбрасывает режим; NPC ждёт.
- UI добавляет в инспекторе Trigger-узла dropdown команд. Target value дописывается в существующее поле команды; для NPC вводится значение из редактора «Идентификатор NPC», для игрока — ник.
