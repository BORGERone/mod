## 3. ОТКРЫТЫЙ ДЕФЕКТ (единственный важный)

### Симптом

Двойной клик по проводу → точка появляется **на проводе**, но:

1. **провод не изгибается через неё** — идёт как шёл;
2. **при перетаскивании точки провод не идёт за ней** (проверено пользователем: он оттащил точки,
   провод остался на месте).

Скриншоты (в репозитории):
`reference/bugshots-328/point-made-on-wire.png` — точка поставлена, провод прямой;
`reference/bugshots-328/point-dragged-wire-stayed.png` — точки оттащены вниз, провод не сдвинулся;
`reference/bugshots-328/point-before-327.png` — как было до 327 (точка стояла рядом с проводом).

Граф на скриншотах: `Реплика #7` (LINE) → карточка `Цель: NPC` (нода преследования, тип TRIGGER).

### Что это значит технически

Отрисовка провода спрашивает маршрут по ключу `порт:цель` **у узла-источника**, а точка лежит в тексте
`SLP2` в поле `animBone` (или `mobilityGroupId` у анимационной ноды) **какого-то узла**. Если ключ не
совпал — `bends()` пуст, провод рисуется прямой штатным `cable(...)`, а точка рисуется отдельно:
ровно то, что на скриншоте.

### Следующие шаги — строго по порядку

**Шаг 0. Лог 328 получен (02.11, 16:49–16:52). Прочитано, факты:**

```
store: #7{0:6=1 }       21 строка store: — точка на узле #7, ключ «порт 0 → узел #6»
store: #7{h0=1 }        один кадр: жест «вытянуть из порта» пишет в хранилище
cable #7 p0 -> …        НИ ОДНОЙ строки «found by ends»
```

Хук `wires()` живой (иначе не было бы `store:`), точка пишется и читается. Провод прямой. Значит
либо перехват `cable(...)` не вызывается для этого провода, либо вызывается с целью ≠ #6 — **на
экране обе версии выглядят одинаково**, различить их может только строка на входе перехвата (329).

Отдельное нерешённое наблюдение: хранилище прыгало `#7{0:6=1 }` ↔ `empty` примерно каждые 5 секунд
(16:51:46–52 пусто, потом опять точка). Не выяснено, переключался ли пользователь между NPC.

Оригинальные диагностические строки 328 (для справки):

```
[settledlands/wires] store: #7{0:9=1} …                    ← что лежит в хранилище
[settledlands/wires] cable #7 p0 -> #9: found by ends, 1 point(s)   ← какой провод искали по концам
```

Нужен лог **после** того, как пользователь поставил точку и потянул её. Без него — не гадать, а
просить. Это уже записано для него в `README-Build328-RU.md`.

**Шаг 1. Прочитать эти строки и выбрать ветку:**

* **A. Строки `store:` нет вообще** → наш миксин `drawPoints`/`drawWires` не выполняется для этого
  экрана (например, пользователь в другом экране графа) или `System.out` перехвачен. Проверять: искать
  в логе `[settledlands/` целиком, убедиться, что jar 328 в `mods`.
* **B. `store:` показывает `h0@…` (ждущий провод), а на экране нарисован обычный провод** → клик
  попал в «ждущий» маршрут вместо настоящей связи. Значит `wireAt`/`connect` расходятся: у
  LINE→TRIGGER связь лежит в `triggers`, а `addRoutePoint` записал `h`. Чинить в
  `NpcWirePointsUi321#wireAt` / `scan` (порядок обхода и порт).
* **C. `store:` показывает `p0t9=1`, а провод прямой** → отрисовка этого провода **не проходит через
  нашу подмену** `cable(...)`. Проверять в первую очередь:
  * `NpcPursuitGraphUiMixin272` (`@Inject` на `drawNode`) — не рисует ли карточка преследования **свой**
    провод сама (`PursuitGraphNode272` содержит свои `curve`/`cable`-пути?);
  * порядок двух инжекторов на один и тот же вызов `cable(...)`: `@ModifyArg` в
    `NpcWhiteWiring302` (цвет) и `@Redirect` в `NpcWirePointsMixin321` (маршрут). Цвет белый
    применяется — значит цепочка жива, но `@Redirect` мог быть «съеден»; проверить, что `@Redirect`
    срабатывает, поставив в него `note("cable-hit", ...)` на **входе** (до проверки точек), и
    посмотреть, печатается ли строка для каждого кадра.
  * **Если подмена не срабатывает** — перейти на другой способ: рисовать **дополнительный** провод
    поверх/вместо (`@Inject` в TAIL `wires(...)`: нарисовать все провода, у которых есть точки,
    своим `curve`, а штатный прямой закрыть цветом фона невозможно — поэтому лучше `@Redirect`; либо
    `@WrapOperation`/`@ModifyExpressionValue`, если версия MixinExtras есть в базовом jar — проверить
    `check_mixin_class.py`).
* **D. `found by ends` печатается, а провод всё равно прямой** → `@Redirect` вернул не то (например,
  `curve` не вызвался из-за отсечения по границам видимости): сравнить с `cable(...)`-обёрткой,
  которая отсекает по `margin` — наш маршрут должен рисоваться **без** этого отсечения, по сегментам.

**Шаг 1a. Что читать в логе 329 (решает вопрос за один проход):**

| В логе | Причина | Правка в 330 |
|---|---|---|
| строк `cable-hit` нет вообще | перехват на `cable(...)` не выполняется: провод рисует другой путь, либо инструкцию занял `@ModifyArg` цвета из `NpcWhiteWiring302` (он на том же вызове) | снять подмену с этой инструкции |
| `cable-hit #7 p0 -> #6, points=1` | перехват жив, ключ совпал → ломается построение сегментов | правка в сегментах `settledlands$cableThroughPoints` |
| `cable-hit #7 p0 -> #X, points=0` | ключ расходится (точка на #6, провод на #X) | `wireAt` / `addBend` |
| `cable-hit #7 p0 -> #6, points=0` | перехват жив, ключ тот же, хранилище узла в тот момент пусто | чтение хранилища (`read`/кеш) |

## 7. Ловушки (стоили мне нескольких сборок)

* **Песочница откатывается на старый HEAD** (`c72f0a3`, merge PR #2). Перед любой работой:
  `git log --oneline -1`; если это не `c7a7380` — `git fetch -q origin arena/99d7691a-mod && git reset --hard -q origin/arena/99d7691a-mod`.
* `git commit -q` без `-A` тащит чужие удаления. Всегда проверять `git status` перед коммитом.
* **Правишь модель — проверь слой жеста.** 325 был «правильным» в хранилище и не изменил ничего,
  потому что миксин съедал клик.
* **Правишь и хранилище, и отрисовку — проверь ключ.** 327 поставил точку на провод, но провод её не
  нашёл: расхождение ключа.
* Снап к сетке (`GRID 8`) сдвигает координаты в тестах: `100→96`, `300→296`. В 327+ магазин **не**
  снапит точку (снапит только `pointOn`, и только если не уводит с провода).
* `wireAt` нельзя считать по прямой между портами — только по нарисованному маршруту.
* Провод не может быть ребром графа: `resolveExecutionTarget` нужна настоящая нода.
* Не отпускать бросок в штатный путь (`contextMenu.showForWire` «вытянуть ноду»).
* `Node.variants/choices/randomBranches/triggers` — `final`; `AbstractWidget` абстрактный; миксин не
  может объявлять не-приватные статики; приватные поля экрана — `0x2`.
* `System.out` в горячем пути (в 328 — диагностика, ограничена 2 раза/сек и только при изменении):
  после подтверждения убрать.
* Нет `java` в PATH, нет системного `pip`, внешние декомпиляторы недоступны.
