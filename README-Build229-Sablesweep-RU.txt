Build 229 «sablesweep» — отчёт для оператора (RU)

ЧТО ЭТО
Хотфикс к 228, собранный без компилятора (zip-хирургия поверх jar228). Меняет ровно одну
вещь в байткоде: две константы в constant pool класса PlayerCorpsePossession.
Всё остальное побайтово как в 228 (349 записей из 352 идентичны).

НАЙДЕННАЯ ПРИЧИНА (по вашему логу от 27.10, jar 228)
1) Watchdog 228 («healStuckIvyBodies», лечение застрявшего тела из сцены смерти IvyDeathScene)
   НИКОГДА не работал. Он искал сущности боксом ±3.0E7 блоков, а мод Sable 2.0.5 в
   SubLevelInclusiveLevelEntityGetter.get() отменяет любой запрос с box.getSize() > 100000.0:
   пишет «Aborting entity get for abnormally large AABB» со стектрейсом и возвращает ПУСТО.
   У бокса ±3.0E7 size = 6.0E7 → запрос отменялся всегда.
   В вашем логе: 3084 такие ошибки с 18:41:01 до 18:49:37, все из healStuckIvyBodies:422 —
   это ~1 раз в секунду, по 14 строк каждая.
2) Итог: невидимое тело 60/60 на месте смерти («Проводник», без модели), шлейф soul-партиклов
   и забитый лог — всё это следствие п.1: фикс 228 просто не выполнялся.

ЧТО СДЕЛАНО В 229
Константы ±3.0E7 в constant pool заменены на ±49999.0 (размер записи тот же, пул не вырос,
размер класса не изменился: 19603 → 19603 байта, отличаются 8 байт).
Размер бокса = (99998*3)/3 = 99998 < 100000 → Sable больше не отменяет запрос.
Watchdog 228 начинает реально искажать тела и лечить их:
  - «stuck ivy body discarded (corpse already present)» — тело убрано, труп уже был;
  - «stuck ivy scene rebased ... conversion completes now» — сцена досчитает и труп появится.
ОШИБКА «Aborting entity get» из нашего мода пропадает вместе с 3084 стектрейсами.
Версия в меню модов: 0.8.0-build229-sablesweep (в ченджлоге описание обновлено).

ОГРАНИЧЕНИЕ (честно)
Бокс в исходнике 228 симметричен относительно НУЛЯ координат, а не вокруг игрока.
Поэтому 229 ловит застрявшие тела в пределах ±49999 блоков по каждой оси.
Для вашего мира (смерть на 37 / 64 / -244, чистилище -154 / 45 / -392) это с запасом.
Правильное решение (перебор сущностей уровня через getAllEntities(), без бокса вообще +
доодевание «неодетого» стокового трупа) лежит готовым исходником в этом архиве:
patch-src/dev/settledlands/npc/PlayerCorpsePossession.java. Для его сборки нужен javac
и classpath Minecraft/NeoForge — в песочнице, где собран 229, они недоступны.

ЧЕГО 229 НЕ ДЕЛАЕТ
Не добавляет нового кода. Если на месте смерти стоит не «застрявшее тело из сцены», а
неодетый стоковый труп (60/60, без модели), 229 его не поправит: для этого нужен пункт
«доодевание», который есть только в исходнике. Поэтому после запуска смотрите лог:
если строк «stuck ivy ...» нет, а невидимая сущность 60/60 осталась — значит это труп,
и нужен скомпилированный билд 230 (исходник готов).

ЧТО НЕ ПРОВЕРЕНО (и почему)

(Maven, Mojang, Adoptium заблокированы сетью; jdk4py — это JRE без jdk.compiler).
Поэтому игровой прогон = ваш плейтест.

ПЛЕЙТЕСТ
1. Положить jar в mods, старый 228 удалить.
2. Убить себя под вселением (/kill), дождаться чистилища, вернуться.
3. Искать в latest.log: «stuck ivy body discarded» / «stuck ivy scene rebased».
   Их наличие = watchdog ожил. Отсутствие «Aborting entity get ... healStuckIvyBodies» = спам ушёл.
4. Прислать latest.log + скриншот места смерти.
