Build 230 «modelfix» — отчёт для оператора (RU)

ЧТО ИСПРАВЛЕНО
Труп больше не теряет модель. Раньше на месте смерти рисовалась коричневая заглушка
(встроенная GuideModel с текстурой guide_npc.png), хотя в NBT трупа модель была прописана.

ПРИЧИНА (по фактам из игры и байткода)
1. GuideRenderer.renderCorpse берёт имя модели так:
       GuideNpc.texturePath()  ->  entityData(DATA_TEXTURE)
   то есть из синхронизированного поля сущности, а НЕ из NBT-профиля. Поэтому
   /data merge ... Guide:{Profile:{Texture:...}} на труп не действовал.
2. Единственное место, где DATA_TEXTURE заполняется, — GuideNpc.applyProfile(),
   причём ПОСЛЕДНЕЙ строкой метода (после setCustomName, Attributes.SCALE,
   refreshDimensions(), setPoseIndex()).
3. PlayerCorpsePossession.dressBodyCorpse вызывает applyProfile() внутри
   `catch (Throwable ignored)`: любое исключение выше по методу молча проглатывалось,
   DATA_TEXTURE оставался пустым, и труп уходил в fallback — без единой строки в логе.
   У /summon-трупа applyProfile() не вызывался вообще, поэтому модель отсутствовала.

ЧТО СДЕЛАНО (без компилятора — правка байткода)
В самое начало applyProfile() вставлены 14 байт, повторяющие штатный код установки поля:
       aload_0
       getfield  GuideNpc.entityData            (#248)
       getstatic GuideNpc.DATA_TEXTURE          (#222)
       aload_1
       getfield  NpcProfile.texture             (#316)
       invokevirtual SynchedEntityData.set      (#252)
Теперь имя модели попадает в синхронизированное поле ДО всей остальной работы метода,
и никакое исключение ниже уже не мешает рендеру. Это байт-в-байт та же последовательность,
что игра выполняет в конце метода (offset 190) — просто раньше и без подстановки "" для null.

ЧЕМ ЭТО БЕЗОПАСНО
* пул констант не менялся (новые константы не добавлялись);
* новых ветвлений нет => новых stack map frames не требуется;
* max_stack уже 5, для вставки нужно 3;
* изменён ровно один метод (applyProfile) — проверено структурным валидатором:
  - пул, поля, интерфейсы, классовые атрибуты — идентичны;
  - code_len 236 -> 250, хвост кода побайтово совпал с исходным;
  - LineNumberTable: все start_pc +14;
  - StackMapTable: 12 фреймов, у первого offset_delta 56 -> 70 (+14), остальное идентично;
  - оба файла разбираются до последнего байта.
* дифф jar 229 -> 230: ровно 3 записи из 352 (GuideNpc.class, toml, patch-info).

ЧЕГО 230 НЕ ДЕЛАЕТ
* не логирует «модель не найдена» (это в BbModelManager, нужен новый код);
* не вкладывает ivy_oleander.bbmodel в jar (файл у вас в .minecraft/settledlands/models есть);
* не трогает HUD трупа (1/60 уже корректно);
* не меняет ничего в чистке застрявших тел (это фикс 229).

ПРОВЕРЕНО ПЕРЕД ВЫДАЧЕЙ
zip целый 352 записи; toml парсится tomllib (0.8.0-build230-modelfix); lang 698+698;
миксины 16+1 все на месте; classfile версии без битых; маркеры 228/229 на месте.
НЕ ПРОВЕРЕНО: запуск игры — компилятора/JVM с Minecraft в песочнице нет,
поэтому игровой прогон = ваш плейтест.

ПЛЕЙТЕСТ
1. В mods положить только build 230 (229 удалить).
2. Умереть под вселением, вернуться из чистилища, дойти до места смерти.
3. Ожидание: тело/труп рисуется моделью Проводника (ivy_oleander), плашка 1/60, вещи в трупе.
4. Если модель всё ещё коричневая — пришлите latest.log и F3+I по трупу; смотрим поле
   Guide.Profile.Texture и наличие строк про модель.
