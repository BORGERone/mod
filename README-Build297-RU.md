# SettledLands 0.8.0 — Build 297 «Условие проверяет свою переменную»

## Что было

295 сломала ноду условия — отменена в 296. При разборе выяснилось главное: нода условия
должна проверять **только ту переменную, которая выставлена в ней самой**, своим оператором и
своим числом. Нода «В радиусе» даёт условию импульс и передаёт найденного игрока — и всё,
она не решает, что условие сравнивает.

## Почему условие проверяло не то

Сборки 290–295 подменяли проверку условия целиком: как только у ноды появлялся синий провод,
хук отбрасывал переменную ноды и сравнивал «тело есть = 1 / тела нет = 0». Твоя переменная не
читалась вообще — ни при игроке в радиусе, ни без него. Отсюда и поведение, которое ты видел.

## Что сделано

Хук на ноде условия удалён. Нода снова считает себя сама:

```
переменная ноды → readVarValue(игрок цепи, нпс, имя, shared, local) → оператор → число → True/False
```

Игрок цепи — это ровно тот игрок, которого нашла нода «В радиусе»: `triggerCheckChain` запускает
обход именно с этого тела (в логе это строка `walk starts at node #5 for BORGER`). То есть ссылка
на игрока, которую передаёт нода радиуса, работает так, как ты описал, без всякой подмены.

Если в радиусе никого нет — цепь не начинается (как в 294/296), условие не считается.

Остальное из 290 осталось как было: провода значений, нода «Урон», нода переменной, `%target%`
в реплике, привязка триггера к телу.

## Что проверить

1. Условие #5 проверяет переменную #5: при игроке в радиусе True/False соответствует **значению
   этой переменной**, а не факту «кто-то есть».
2. Помеять переменную у игрока (или взять другого игрока с другим значением) — ветка меняется.
   Это и есть доказательство, что читается переменная, а не «есть/нет тело».
3. При пустом радиусе по-прежнему ничего не печатается.
4. В списке модов имя `Settled Lands 0.8.0-build297-if-own-variable`.

## Гейты

`validate_jar` (456 записей, 408 классов), `jvm_verify` (408 классов), `check_mixin_class`
(39 миксинов, 1385 внешних ссылок, 0 новых против 296), `dangling_refs` (0 удалённых членов),
`verify_jar` — пройдены. В собранном классе миксина нет ни `evalIfNode`, ни `ifValue`, ни
`settledlands$ifFromValue` — подмена действительно удалена.
