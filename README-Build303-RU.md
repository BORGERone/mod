# SettledLands 0.8.0 — Build 303 «Без вылета: синие провода, тумблер на месте, быстрее преследование»

## Вылет Build 302 и что в нём было не так

```
Mixin apply failed settledlands.mixins.json:NpcWhiteWiring302
  contains non-private static field COL_CABLE_WHITE:I
```

Mixin-класс не имеет права объявлять статическое поле, кроме приватного — он выбрасывает
**весь класс**, а с ним падает клиент в момент первой загрузки экрана графа, то есть при открытии
диалога с правкой. В 302 два белых mixin-класса объявляли в себе цвет как `public static final`.
Теперь цвета берутся из `PursuitGraphNode272` (обычный класс), в mixin-классах полей нет вообще.

Заодно гейт `check_mixin_class.py` теперь проверяет это правило — со статическим полем в миксине
сборка не пройдёт.

## Что произошло и почему (301)

Синие провода перестали рисоваться не из-за самих проводов. Код, который их рисует, в 301 не
менялся ни на байт — он совпадает с 300 побайтово. Сломали их белые крючки, добавленные в тот же
mixin-класс: хук на заливку портов (это единственный хук в чужой метод Minecraft, а не в наш
собственный) не нашёл цель, а Mixin при неattachнутом хуке выбрасывает **весь класс** — вместе с
синим проходом, который жил в нём же.

Сделано так, чтобы это не могло повториться: синий проход сидит в классе ровно в том виде, в каком
он работал в 300, а белая проводка вынесена в отдельные mixin-классы с `require = 0`. Белые кабели и
белые порты теперь ещё и в разных классах — порты белит ровно тот хук, который может не найти цель.
Если он её не найдёт, останутся цветные порты, всё остальное не заденет.

## Что сделано

### Синие провода

```
синий проход       → тот же класс, что в 300 (побайтово), ничего не тронуто
белые кабели       → отдельный класс NpcWhiteWiring302, require = 0
белые порты        → отдельный класс NpcWhitePorts302, require = 0
```

### Тумблер «Завершить преследование»

Стоял седьмой строкой панели и на невысоком окне обрезался вместе со всем, что ниже. Теперь он
второй, сразу под переключателем типа цели:

```
Тип цели: NPC            ← y + 0
Завершить преследование  ← y + 35   (было y + 180)
Цель:                    ← y + 59
Дистанция:               ← y + 94
Догонять с:              ← y + 129
Ускорение догона:        ← y + 164
Снять связь / Удалить    ← y + 199
Выход: Цель → %pursuit%  ← y + 221
```

### Поле «Дистанция:»

Это стойка (standoff): на какое расстояние NPC подходит к цели и останавливается. Дальше — уже
погоня, ближе он не подходит никогда. 1.0–8.0 блоков, по умолчанию 1.6. Рядом:
«Догонять с:» — с какого расстояния включается догон (2–48, по умолчанию 8), «Ускорение догона:» —
во сколько раз быстрее идёт догон (1.0–3.0, по умолчанию 1.5).

### Скорости

```
преследование (обычная погоня) = бывшая скорость догона   ≈ 0.4 / атрибут   (+26 % к 301)
догон                          = она же × 1.4 … × 3.4    ≈ 0.56 … 1.36     (всегда быстрее)
```

Множитель догона: `1.4 + (ускорение − 1) × ramp`, где ramp плавно растёт от порога «Догонять с:»
до трёх блоков. Ограничения и смысл «Ускорения догона» не менялись, сохранённые ноды читаются как
раньше.

### Синий пин у «В радиусе»

У карточки «В радиусе» пин рисовался по координатам карточки pursuit, а она шире — пин уезжал с
порта. Теперь рисуется там, где реально начинается провод; радиус по-прежнему `2.0 × зум`.

## Что проверить

1. Синие провода видны — целиком, линией, без мигания, при любом зуме и после перетаскивания.
2. Порт и кабель обычной ноды белые (порты — только квадраты 10×10 по краям).
3. В панели ноды преследования второй строкой стоит «Завершить преследование», переключается и
   меняет подпись на «… ✓»; после перезапуска состояние сохраняется.
4. «Дистанция:» — это стойка в блоках; на 1.6 NPC подходит на 1.6 блока и встаёт.
5. Преследование идёт заметно быстрее, чем в 301; догон — ещё быстрее, и разгон тем сильнее, чем
   дальше цель и чем больше «Ускорение догона».
6. «В радиусе» — синий пин стоит на порту, провод начинается из него.
