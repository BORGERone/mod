# SettledLands 0.8.0 — Build 318 «Копирование и вставка нод»

## Как это работает

- **Ctrl+C** — копирует выделение (если выделено несколько нод — весь набор, иначе выбранную).
- **Ctrl+V** — вставляет в текущий граф. Вставленные ноды становятся выделенными, вся вставка — один
  шаг undo (`Ctrl+Z` отменяет её целиком).
- Пока фокус в текстовом поле, Ctrl+C/Ctrl+V работают как обычно — с текстом строки.

Копируется **системный буфер обмена**, обычным текстом: блок можно перенести в другой граф, к другому
NPC, в другой мир, вставить в блокнот, поправить руками и вставить обратно.

## Формат

```
SLGRAPH318 1
node id=5 type=0 x=120 y=40 text="Привет" action="" next=7 choices=5,9
node id=7 type=3 x=320 y=40 text="" varValue=3 falseNext=5 triggers=5
```

Первая строка — заголовок и версия раскладки. Дальше по строке на ноду: `ключ=значение`, строки в
кавычках с экранированием (`\"`, `\\`, `\n`, `\t`), списки через запятую. Пишутся **все** поля ноды —
текст, действие, уровень отношений, очки, условие, кулдауны, урон, время, радиус, анимация, катсцена,
варианты реплик, а также связи: `next`, `falseNext`, `varInputNode` (синий провод), `choices`,
`randomBranches`, `triggers`.

Неизвестные ключи при вставке игнорируются, отсутствующие остаются значениями по умолчанию — старый
текст из буфера не сломает новую сборку.

## Правила связывания (как в Unreal Engine)

- Связь переносится, только если **оба** её конца были в выделении; ссылка пересчитывается на новые id.
- Связь, уходящая за пределы выделения, обрезается (`next = -1`), списки (`choices`, `randomBranches`,
  `triggers`) теряют только внешние элементы.
- **Входная нода не копируется никогда**: вход в графе один, второй сделал бы диалог недостижимым.
- Вставка сдвигается на +24/+24 от исходных координат, координаты подрезаются по `MAX_COORD`.
- Если после вставки получилось бы больше `MAX_NODES` (2048) — вставка отклоняется целиком, статус
  «Вставка не удалась: limit», граф не меняется.

## Что добавлено

```
NpcGraphClipboard318     формат, перенумерация id, откат при ошибке — обычный Java, без Minecraft
NpcClipboard318          два вызова буфера: Minecraft.getInstance().keyboardHandler.get/setClipboard
NpcClipboardMixin318     Ctrl+C / Ctrl+V на экране графа, HEAD keyPressed
ru_ru.json, en_us.json   +4 статуса: clip_copy / clip_empty / clip_paste / clip_fail
```

Все изменения графа по-прежнему уходят на сервер одним `Ctrl+S` (экран сохраняет граф целиком), поэтому
вставке дополнительный сетевой путь не нужен.

```
  многострочный текст с кавычками, варианты реплик, отказ на мусоре и на входной ноде
```

Проверка внешних API: гейт фазы D по-прежнему требует, чтобы вызов был подтверждён базовым jar. Буфер —
исключение, он внесён в `CONFIRMED_EXTERNAL` с обоснованием: `Minecraft#keyboardHandler` — публичное поле
клиента, `KeyboardHandler#getClipboard/#setClipboard` — ровно та пара, которой ванильный `EditBox`
делает Ctrl+C/Ctrl+V в 1.21.1 (сверено по исходникам модов 1.21: Jade, ProjectRed, RebornCore). Всё
остальное — как было: 1388 внешних ссылок, 0 новых.

## Что осталось на следующий шаг

Пункты «Копировать» / «Вставить» в правом клике. Штатное меню палитры — фиксированная таблица строк
(`TOTAL_ROWS`, своя отрисовка, скролл и попадание по строке), поэтому встраивание двух строк — отдельная
аккуратная правка этого класса, а не одна строка кода. Сейчас работают клавиши.

## Что проверить

1. Выделить рамкой три ноды → Ctrl+C → новый граф → Ctrl+V: три ноды, все значения на месте, связи между
   ними целы.
2. Ctrl+Z — вся вставка снимается одним шагом.
3. Скопировать одну ноду, вставить: связи наружу обрезаны, в графе по-прежнему один вход.
4. Вставить в блокнот и обратно — текст читаемый, кириллица, кавычки и переносы строк целы.
