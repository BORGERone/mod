# SettledLands 0.8.0 — Build 321 «Точки перегиба на проводах»

## Как это работает

| действие | что происходит |
|---|---|
| **двойной клик по проводу** | в этом месте появляется точка перегиба |
| **перетащить точку** | провод идёт через новое место |
| **двойной клик по точке** | точка удаляется, провод снова прямой |
| обычный клик по проводу | ничего (как раньше) |

Провод рисуется **той же самой** штатной кривой, просто по сегментам: выходной порт → точки →
входной порт. Поэтому толщина, цвет, пунктир и поведение при зуме не отличаются от обычного провода —
он просто идёт туда, куда его положили.

Точки ставятся по сетке 8 — той же, к которой холст привязывает ноды.

## Это только визуал

Соединение не меняется ни в чём: источник по-прежнему указывает на ту же ноду, сервер читает те же
поля, диалог выполняется ровно так же. Гейт это проверяет отдельно — класс точек **не имеет права
присваивать** ни `next`, ни `falseNext`, ни `choices`, ни `triggers`, ни `randomBranches`, ни
`varInputNode`. Провод определяется той тройкой, которая у него уже была: нода, порт, цель.

## Где хранятся точки

У ноды нет свободного поля, поэтому перегибы всех её проводов лежат текстом в одном строковом поле,
выбранном так, чтобы **свой** тип ноды его не читал:

```
тип ноды             поле
анимация (9)         mobilityGroupId
все остальные        animBone
```

Формат: `SLP1|p<порт>t<цель>:x,y x,y|…`. Оба поля сохраняются в NBT графа, поэтому точки едут вместе
с графом, через Ctrl+C/Ctrl+V, через undo и после перезахода в мир.

Защита: чужой текст (значение поля без маркера `SLP1`) никогда не перезаписывается — если поле уже
занято чем-то не нашим, перегибы работают в текущей сессии и просто не сохраняются. Гейт и тест
проверяют это явно.

## Что добавлено

```
NpcWirePoints321           хранилище и формат текста, обычный Java без Minecraft
NpcWirePoints321$Handle    один перегиб
NpcWirePointsUi321         квадратики-маркеры, попадание мышью, перевод координат
NpcWirePointsUi321$Wire    идентификация провода
NpcWirePointsMixin321      @Redirect на cable в wires() + 3 хука мыши (клик, перетаскивание, отпускание)
```

Маркеры рисуются в экранных координатах и следят за зумом (но не меньше 3 px), подсвечиваются под
курсором. Любое изменение зовёт штатный `changed()` — сохранение обычное, Ctrl+S.

## Гейт

Новый `tools/wire_points_check.py`:

```
3 класса + 2 вложенных на месте, миксин в client-списке
в классе точек нет присваиваний ни одному полю связи (иначе гейт падает)
оба поля (animBone, mobilityGroupId) читаются
круговая проверка tools/tests/WirePointsRoundTrip.java на самом jar, без игры:
  текст формата, сетка 8, перенос в другую ноду, поле анимационной ноды,
  отказ перезаписи чужого текста, связь остаётся целой после add/move/delete
```

## Что проверить

1. Двойной клик по проводу — появилась точка, провод изогнулся.
2. Потянуть точку — провод следует за ней; узел-нода не сдвинулась.
3. Двойной клик по точке — провод снова прямой.
4. Ctrl+S, закрыть и открыть редактор — точки на месте.
5. Отменить (Ctrl+Z) после перетаскивания — точка вернулась на место.
6. Диалог с NPC работает как раньше (это только вид).
