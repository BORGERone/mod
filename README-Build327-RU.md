# SettledLands 0.8.0 — Build 327 «Точка ставится на провод, а не рядом с ним»

## Что было не так

Две дыры, обе дают одно и то же: **белый квадратик стоит на пустом холсте, провод через него не идёт.**

1. **Точка ставилась туда, где курсор, а не туда, где провод.** Попадание по проводу берётся с запасом
   (до 6 пикселей), а потом координата ещё и притягивалась к сетке в 8 единиц. Итог — точка вставала
   рядом с проводом, а не на нём: провод шёл мимо, изгиба не было видно.
2. **Точка могла попасть в «ключ», который экран вообще не рисует.** Экран рисует каждый провод со
   своим номером порта: `next`, `choices`, `triggers` — порт 0, ложная ветка условия — порт 1,
   **ветки случайной ноды — номер ветки**. Клик по ветке случайной ноды записывался с портом 0, а
   провод ищется по ключу `номер ветки:цель`. Такой точки не находил ни один провод: рисовалась
   точка, а провод через неё не проходил никогда.

## Что теперь

**Клик переносится на сам провод.** Находится ближайшая точка на той кривой, которая нарисована, и
точка ставится именно там. Сетка применяется только если не сдвигает точку с провода; если сдвигает —
остаётся точное место. И сохранение больше **не притягивает** точку к сетке второй раз — раньше именно
это сдвигало только что поставленную точку обратно с провода.

```
   было:  клик рядом ──●        (● рядом с проводом, изгиба нет)
   стало: клик рядом ──●──       (● на проводе, провод изогнут через неё)
```

**Порт берётся тот, которым провод нарисован** — включая ветки случайной ноды. А точка, чей ключ экран
не рисует, теперь просто **убирается**, а не висит квадратиком на пустом месте: такое больше не
накопится.

## Что изменено

```
NpcWirePointsUi321      wireAt: порт ветки случайной ноды = номер ветки (было 0);
                        route/nearestOnRoute — провод как ломаная, общий и для попадания, и для места;
                        pointOn — координаты точки НА проводе (проекция клика, сетка только по необходимости);
                        nearestOnSegment — самая близкая точка кривой; segmentDistance через неё
NpcWirePoints321        drawn(node, port, to) — «экран правда рисует провод с таким ключом» (зеркало
                        того, как wires() перебирает поля); по нему чистится всё, что нарисовать нельзя;
                        addBend/addRoutePoint/attach/movePoint больше не притягивают точку к сетке
NpcWirePointsMixin321   при создании точки берутся координаты pointOn(canvas, wire, …), а не курсор
```

Разметка хранения не менялась: `SLP2`, `p<порт>t<цель>:x,y …`, `h<порт>@x,y …`.

## Что проверить

1. Двойной клик **по проводу** → точка появляется **на проводе**, провод изгибается через неё.
2. Тот же клик чуть в стороне от провода (в пределах пары пикселей) → точка всё равно на проводе.
3. Двойной клик по **ветке случайной ноды** → точка на этой ветке, провод изгибается.
4. Двойной клик по пустому месту, где провода нет → ничего не появляется.
5. Такого, как на скриншоте (квадратик без провода), больше быть не должно. Если он остался — скажите,
   и я пойду дальше по этому следу: тогда это рисует не мой код.
