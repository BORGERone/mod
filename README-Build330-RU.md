# SettledLands 0.8.0 — Build 330 «Провод гнётся: перехват перенесён на сам провод»

## Что было не так

Лог 329 дал ответ, которого не мог дать ни один скриншот. За всю сессию:

```
[settledlands/wires] store: #7{0:6=1 }      ← 12 строк: хранилище держит точку
[settledlands/wires] cable-hit …            ← 0 строк: перехват НЕ ВЫПОЛНЯЛСЯ ни разу
```

При этом провод был **белым** — а белый цвет ставит `@ModifyArg` из `NpcWhiteWiring302`, висящий
**на том же самом вызове** `cable(...)`, который пытался перехватить 321. То есть вызов жив и
проходит через хук цвета, а наш перехват на этом же месте вызова не сработал ни разу: инструкцию
забрал другой инжектор. Пять сборок (321–329) искали причину в ключах, портах и хранилище — а
перехвата просто не было.

**Вывод: перехват на месте вызова ненадёжен. Хук на самом методе — надёжен.**

## Что теперь

Перехват стоит **на входе самого `cable(...)`**, а не на вызове внутри `wires(...)`:

```
   было (321–329):  wires() ──[вызов cable]── ✗ место занято хуком цвета
   стало  (330):    wires() ── cable() ──► наш вход ──► штатное тело, если точек нет
```

Через `cable(...)` проходит **любой** нарисованный провод, откуда бы его ни рисовали — из прохода
проводов, из карточки, из подсветки. Поэтому маршрут через точки теперь применяется независимо от
того, кто и как вызвал отрисовку.

## Оптимизация

- **Граф без точек не платит ничего.** Одна проверка `anyPoints()` на провод, с кэшем на 500 мс,
  который сбрасывается при любой записи в хранилище — точка попадает в кадр сразу после клика.
  Раньше (328) каждый провод в каждом кадре делал обход графа в поисках маршрута по концам.
- **Отсечение по видимости** как в штатном `cable`: если весь маршрут (порт → точки → порт) вне
  канваса, проводу возвращается `0` без построения геометрии.
- **Строки в лог только по факту**: `cable … routed through N point(s)` пишется, когда маршрут
  реально применён (не чаще 2 раз/сек на провод). Строка «промаха» — только первые 24 разных
  провода за сессию, дальше ноль работы.
- Провод без точек **не копируется и не перерисовывается**: обработчик выходит, штатное тело
  работает как всегда — ни одного лишнего вершиного буфера.

## Что проверить

1. Открыть граф `Реплика #7` → карточка `Цель: NPC`.
2. Двойной клик по проводу — точка на проводе, **провод изгибается через неё** (появляется
   характерный излом в месте точки, а не прямая дуга).
3. Потянуть точку — **провод идёт за ней** в том же кадре.
4. В логе должна появиться строка:
   `[settledlands/wires] cable #7 p0 -> #6: routed through 1 point(s)`

Если после этого провод всё ещё прямой — пришлите `latest.log`: в нём будет либо строка `cable …`
(тогда дело в геометрии), либо строка `cable … no points for this key` (тогда дело в ключе), либо
ничего (тогда провод рисуется вообще не через `cable`, и это следующий шаг).

## Что изменено

```
NpcWirePoints321        anyPoints(graph) — есть ли в графе хоть одна точка (кэш 500 мс, сброс при
                        записи); onceRoom()/noteOnce() — одноразовые строки с лимитом
NpcWirePointsMixin321   вместо @Redirect на вызове cable(...) — @Inject(HEAD, cancellable) в сам
                        cable(...): маршрут через точки, отсечение по видимости, возврат счётчика
                        квадов; без точек — обычный выход, штатное тело без изменений
```

Разметка хранения не менялась: `SLP2`, `p<порт>t<цель>:x,y …`, `h<порт>@x,y …`.
