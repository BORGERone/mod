# SettledLands 0.8.0 — Build 333 «Список забирает клик первым»

## Почему клик уходил в ноду

Список рисуется последним — `render` поднимает его на Z+500, он лежит поверх всего. А клик
искался поздно: тело `mouseClicked` сначала отдаёт клик карточке авто-ИИ, потом ноде
характеристик, и только в самом конце доходит до штатного кода, который вообще знает, что
какой-то список открыт. Перед телом метода стоят ещё четыре HEAD-хука (272 — меню карточки
преследования, 290 — синие пины, 320 — тумблер радиуса, 321 — точки проводов), и каждый из них
сам щупает холст; про открытый список не знает ни один.

Поэтому строка списка, лежавшая над карточкой ноды, отдавала клик ноде: нода выбиралась или
начинала тянуться, а список до клика не доходил — профессия не менялась.

## Что сделано

Один миксин — `NpcDropdownFirst333`, **первым** в клиентском списке миксинов, чтобы его HEAD-хук
срабатывал раньше хуков 272–321. Если у экрана есть открытый список, клик отдаётся списку и
дальше не идёт:

- ЛКМ по строке — выбирается строка под курсором;
- клик мимо списка — только закрывает его;
- правая/средняя кнопка по списку — только закрывает;
- ни нода, ни карточка, ни пин, ни тумблер, ни точка, ни провод не трогаются.

Список рисуется из поля `openDropdown`, и хук читает **то же поле** — что на экране, то и забирает
клик; разойтись они не могут. Прокрутка не тронута: `mouseScrolled` и раньше спрашивал открытый
список первым (`popupScrolled`), это проверяется гейтом.

## Что проверить

1. Нода характеристик → строка профессии → список открыт.
2. Подвинуть граф так, чтобы **под открытым списком** оказалась нода.
3. Клик по строкам списка над этой нодой → профессия меняется, нода не выбирается и не тянется.
4. Клик мимо списка → список закрывается, граф не реагирует.
5. Колесо над списком → список прокручивается.
