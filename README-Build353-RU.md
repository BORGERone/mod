# SettledLands 0.8.0 — Build 353 «Радиус у блока» (джарник целиком)

Та же сборка, что 352, но загружается.

## Причина падения 352

В джарнике не было **вложенного класса** `BlockTriggerStore351$Entry` — он компилировался, но не
копировался в архив. Загрузчик перебирает методы классов мода, наткнулся на сигнатуру с этим типом и
упал: `NoClassDefFoundError: dev/settledlands/npc/BlockTriggerStore351$Entry`, мод не собрался
(«Failed to register automatic subscribers»). Дело не в коде радиуса — код работал бы; не хватало
одного файла в архиве.

Почему это пропустили гейты: все они проверяли **то, что в джарнике есть** (`jvm_verify` — структуру
классов, `check_mixin_class` — точки инъекции, сравнение с базой — только классы, которые есть в обеих
сборках). Отсутствие класса не проверял никто.

## Что сделано

1. Класс на месте: `dev/settledlands/npc/BlockTriggerStore351$Entry` (522 записи в архиве против 521).
2. Сам гейт закрыт навсегда: `tools/dangling_refs.py` теперь падает, если код мода ссылается на
   **свой же** класс, которого в архиве нет. Проверяются оба пути, которыми тип попадает в класс, —
   запись в пуле констант и **дескриптор** метода/поля (именно второй убил 352). На сломанном 352
   гейт воспроизводит падение:

   ```
   ! dev/settledlands/npc/BlockTrigger352 refers to
     dev/settledlands/npc/BlockTriggerStore351$Entry (no such class in the jar)
   ```
3. `tools/block_trigger_check.py` тоже требует `BlockTriggerStore351$Entry.class` в архиве.
4. Сломанный 352 снят из дерева и убран с Drive.

## Технические заметки

* Состав, поведение и все внешние вызовы — как в 352: **0 новых** обращений к Minecraft/NeoForge
  против 351, `ServerTickEvent.Post` уже используется базовым jar.
* Один проход на 8 тиков, только по индексу измерения, `store.size()==0` или нет игроков — выход до
  всякой работы; флаги «есть радиус» / «есть кольцо» считаются при сохранении графа.
* Ошибка в проходе — одна строка в лог и пасс выключается до перезапуска.
* Новый гейт ловит ровно тот класс ошибок, из-за которого упала 352, — и на любой будущей сборке.
