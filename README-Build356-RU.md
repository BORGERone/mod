# SettledLands 0.8.0 — Build 356 «Флаг радиуса сохраняется»

Одна правка, и она объясняет вчерашнее: тумблер «Видимость радиуса» теперь действительно
выключается — потому что флаг наконец **записывается в граф**, а не теряется при сохранении.

## Что было не так

В 355 строка «Видимость» уже сохраняла граф по клику, но значение всё равно мгновенно возвращалось
на «включено». Дело не в клике, а в записи флага:

* `NpcDialogueGraph#save` пишет ключ `TimerRepeat` **только для ноды таймера** (`type == 8`).
* `NpcDialogueGraph#load` читает этот ключ **для любой ноды** и, если ключа нет, подставляет
  **`true`**.

То есть у ноды «В радиусе» (и «Цель») флаг вообще не сохранялся: каждое сохранение его выбрасывало,
а каждое чтение возвращало «да». Дальше по цепочке: клиент отправляет граф на сервер → сервер
применяет его (`GuideNpc.applyConfig` → `load`) и присылает снимок обратно → экран перечитывает граф
(`applySnapshot` → `load`) → строка показывает «да», а сервер снова рисует кольцо.

Проверка на реальных классах (не на словах) это показывает дословно:

```
BASE    check=absent radius=absent timer=false   ← save выбросил флаг ноды «В радиусе» и «Цель»
DEFAULT check=true   radius=true                 ← load подставил «да» (это и видел автор)
MIXIN   check=false  radius=false  timer=false   ← после правки ключ на месте
LOAD    check=false  radius=false  timer=false   ← load его честно читает
ON      check=true                               ← включённое остаётся включённым
```

## Что сделано

Один общий миксин `RadiusFlagSave356Mixin` на `NpcDialogueGraph#save`: в конце сохранения у каждой
ноды «В радиусе» и «Цель» в её тег кладётся `TimerRepeat` с текущим значением флага. Читатель не
тронут — `load` уже умеет читать этот ключ у любой ноды, поэтому никакой второй правки не нужно.

* Миксин **общий** (не клиентский): сервер сохраняет тот же граф и обязан писать тот же ключ.
* Нода таймера не затронута: её ветка `type == 8` осталась как была.
* Кольцо — по-прежнему дело сервера; теперь у сервера есть правильное значение флага и после
  сохранения, и после перезапуска.

## Что проверить

1. Открой блок (или НПС) жезлом, выбери ноду «В радиусе».
2. Нажми «Видимость радиуса: да» — кольцо появилось; нажми ещё раз — кольцо **пропало** и строка
   показывает **«нет»**, а не «да».
3. Закрой редактор и открой снова — строка по-прежнему «нет», кольца нет.
4. Выйди из мира и зайди заново — «нет» и нет кольца.
5. Включи обратно, сохрани/перезайди — «да» и кольцо на месте.

## Технические заметки

* Новых обращений к Minecraft/NeoForge — **ноль** против 355 (1392 внешние ссылки, те же).
* Новых языковых ключей нет: строка «Видимость радиуса: да/нет» из 354.
* Ключ `TimerRepeat` — тот же, что у ноды таймера; отдельного поля и формата не вводится, старые
  сохранения читаются как раньше (нет ключа → «да», как было до 356).
* Правка идёт только по тегу, который `save` уже собрал: ни один вызов сохранения не обходится
  стороной — НПС, блоки (`settledlands_block_triggers`), профили, буфер обмена.
* Ошибка в любом пути по-прежнему сообщается одной строкой и не роняет сервер.
