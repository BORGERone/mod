# Settled Lands — сборка 371 (door-shut)

Файл мода: `settledlands-0.8.0-build371-door-shut.jar`
Версия в игре: `0.8.0-build371-door-shut`
Собрано из базы: `settledlands-0.8.0-build370-door-tab.jar`

## Почему дверь открывалась «на секунду» и через неё проходили

Две дырки, обе — одна и та же ошибка в разной одежде.

**1. Клик только отменялся.** Игра не читает «событие отменено» как ответ на вопрос «можно ли
использовать блок». Она читает два поля — `useBlock` и `useItem`, — и для этого `PlayerInteractEvent` и
существует. Теперь `DoorEvents368` явно ставит `Event.Result.DENY` в оба (и для клика ключом, и для
пустой руки), а отмена события остаётся для тех слушателей, кто эти поля не смотрит.

**2. Клиент угадывал — и никто его не поправлял.** Клиент открывает дверь в момент клика и только
потом спрашивает сервер. Отказанный клик раньше **ничего не менял на сервере**, значит и отправить
клиенту было нечего — игрок продолжал смотреть на открытую дверь, пока до него не дойдёт что-то ещё.
Вот это и была «секунда». Теперь сервер в том же тике закрывает дверь и отправляет её состояние
клиентам (`Level#sendBlockUpdated`), то есть ответ приходит сразу, а не когда-нибудь.

**3. Замок перестал быть мнением одного события.** Добавлен сторож `DoorGuard371`: каждый тик он
смотрит на срез запертых дверей (64 за тик, список пересобирается раз в 40 тиков) и закрывает любую
запертую дверь, которая открыта, если её открыл не гайд. Это накрывает всё остальное: другие моды,
редстоун, поршни, странные пути взаимодействия. Дверь, через которую идёт гайд, не трогается.

## Что не менялось

Сама механика: ключ `settledlands:door_key` (вкладка мода, `/give`), запирание/отпирание по ПКМ,
запрет слома игроком, охрана от мобов и взрывов (`require = 0`), проход гайдов и закрывание дверей за
собой.

## Как проверить

1. Поставить дверь, ПКМ ключом → «Дверь заперта ключом».
2. ПКМ рукой: дверь **не дёргается вообще** (не открывается ни на кадр), в action bar «Дверь заперта».
3. Попробовать пройти в проём — не проходит; дверь остаётся закрытой визуально и по коллизии.
4. Сломать — нельзя. Позвать гайда — проходит.
5. Если что-то всё же открывает запертую дверь (редстоун, поршень, другой мод) — сторож закроет её в
   пределах доли секунды.

## Не подтверждено в игре

Ничего из 371 в игре не проверялось. Четыре новых вызова (`setUseBlock`, `setUseItem`,
`Event.Result.DENY`, `Level#sendBlockUpdated`) сверены по публичному API NeoForge 1.21.1, а не запуском;
все они выполняются только в момент клика по запертой двери, поэтому ошибка в них не может помешать
запуску игры — в худшем случае клик снова откроет дверь, и об этом будет строка в логе.

Проверки: 21 гейт зелёный, `verify_jar --base 370` PASS (0 удалённых членов), `validate_jar` OK. Гейт
`door_lock_check` теперь **требует**: `setUseBlock` + `DENY`, `sendBlockUpdated`, наличие сторожа
`DoorGuard371`, который закрывает дверь, а также (как и раньше) регистрацию ключа, отмену слома, охрану
`destroyBlock`, ответ `canOpenDoors`, запись ключа во вкладку и формат файла замка (проба расширена
разбором ключа `измерение@x,y,z`).

Состав jar: 557 записей, 507 классов, 41 общий миксин (+2 с build 368), 42 клиентских.
