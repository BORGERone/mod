# Settled Lands — сборка 372 (door-log)

Файл мода: `settledlands-0.8.0-build372-door-log.jar`
Версия в игре: `0.8.0-build372-door-log`
Собрано из базы: `settledlands-0.8.0-build371-door-shut.jar`

## Зачем эта сборка

«Ничего не поменялось» может означать четыре разные вещи, и по логу это видно за одну строку, а по
описанию — нет. Поэтому поведение не меняется, меняется только то, что мод **пишет в лог**:

| строка в `latest.log` | что она значит |
|---|---|
| `door: settledlands:door_key registered` | ключ существует; если строки нет — предмет не зарегистрировался и запирать нечем |
| `door: the door at 12, 64, -30 is locked by the key, 2 place(s) locked` | ключ сработал, замок записан, координаты те |
| `door: the door at 12, 64, -30 is unlocked by the key` | ключ снял замок |
| `door: the click on the locked door at 12, 64, -30 was refused (useBlock=DENY), open now=false` | клик по запертой двери отклонён, и дверь после этого закрыта |
| `door: the key was used on Block{...} at 12, 64, -30 - that is not a DoorBlock` | вы бьёте ключом по блоку, который мод не считает дверью (например, дверь другого мода) |
| `door: the guard closed the locked door at …` | сторож закрыл запертую дверь, которую кто-то открыл в обход |
| `door key added to the creative tab settledlands:guide` | ключ попал во вкладку мода |

Максимум восемь строк за сессию, потом тишина — это отчёт, а не спам.

## Как снять отчёт

1. Запустить игру, зайти в мир.
2. Взять ключ (вкладка мода или `/give @s settledlands:door_key`), поставить дверь, ПКМ ключом.
3. ПКМ по этой двери рукой, попробовать пройти, попробовать сломать.
4. Выйти из игры и прислать `latest.log` (`.minecraft/logs/latest.log`) — по строкам `door:` выше сразу
   понятно, где обрывается цепочка.

## Что не менялось

Вся механика 371: запрет `useBlock`/`useItem`, отправка закрытого состояния клиенту, сторож,
`require = 0` у миксинов, запись ключа во вкладку.

Проверки: 21 гейт зелёный, `verify_jar --base 371` PASS (0 удалённых членов), `validate_jar` OK. Гейт
`door_lock_check` теперь **требует** наличия всех четырёх отчётных строк — на 371-м jar он падает
именно на них, то есть сборка без диагностики больше не пройдёт.

Состав jar: 557 записей, 507 классов, 41 общий миксин, 42 клиентских.
