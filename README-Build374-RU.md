## Сначала про присланный лог: 373 вы не проверяли

`latest-10.log` показывает, что сборка 373 **загрузилась** (строка 132 и 472 — `settledlands-0.8.0-build373-door-refuse.jar`,
ошибок миксинов нет), но клиент умер на экране загрузки в 13:47:09, **до создания мира**. Значит про дверь
этот запуск не говорит ничего — ни «сломалось», ни «починилось».

Что произошло по шагам:

1. `Failed to create mod instance. ModID: createdeco` — Create Deco упал в своей инициализации:
   `Catwalks.build` → Create `CTSpriteShifter.getCT` → ponder `StitchedSprite.<init>` →
   `ConcurrentModificationException` в `HashMap.computeIfAbsent`. Это гонка: Create-аддоны
   инициализируются параллельно и одновременно лезут в одну и ту же карту спрайтов Create.
2. Из-за упавшего мода загрузчик ушёл в «broken mod state» (в логе: `Cowardly refusing to send event …`),
   и регистрация кейбиндов не выполнилась.
3. Первый клик мышью на экране загрузки убил клиент: Quark `AutoWalkKeybindModule$Client.acceptInput` →
   `NullPointerException: this.keybind is null` → `Unreported exception thrown` →
   `crash-2026-11-05_13.47.09-client.txt`.
4. В логе **ноль** строк с `door:`, мир не загружался, и ни одного кадра из `dev.settledlands` в краше нет.

Тот же краш был и в логе предыдущей сессии: там проиграл гонку другой аддон — `createrailwaysnavigator`,
и падал он ровно в том же месте (`ponder StitchedSprite`). То есть виноват не один мод, а параллельная
инициализация Create-аддонов: каждый запуск проигрывает кто-то другой.

## Что нового в 374

**Механику я не менял.** Отказ по-прежнему стоит там, где дверь открывается —
`DoorBlock#useWithoutItem(...)`, поэтому запертая дверь не открывается вообще, и тика, в который можно
проскочить, нет. 374 добавляет только доказательство:

1. **Первое попадание в метод пишется в лог.** `door: DoorBlock#useWithoutItem was reached at <позиция>, locked=<true|false>`
   — строка пишется из самого перехвата. Если она есть — перехват живой; если в ней `locked=false` —
   замок не найден на этой позиции. Это две единственные причины, по которым дверь может открыться,
   и теперь обе видны в одной строке.
2. **Строка регистрации ключа содержит номер сборки:** `door: settledlands:door_key registered (build 374 door-proof)`.
   Теперь по логу всегда видно, какой jar его писал.
3. **Перехват обёрнут в `try/catch`**: исключение внутри двери больше не может съесть клик и не может
   уронить игру.

## Что проверить

1. Запустить игру. **Не кликать мышью, пока висит экран загрузки** — именно клик превращает «один мод не
   инициализировался» в вылет через Quark.
2. После запуска заглянуть в `latest.log` на строку `Failed to create mod instance`. Если она есть —
   сессия негодная, перезапустить (гонка случайная: обычно следующий запуск проходит).
3. Взять ключ в креативе (вкладка мода), ткнуть им в дверь — дверь заперта.
4. **Упереться в дверь и быстро кликать.** Ожидаемо: дверь не открывается ни на кадр, проскочить нельзя.
5. Моб не должен её сломать; проводник НПС должен по-прежнему проходить через запертую дверь и
   закрывать её за собой.

## Как читать лог после проверки

- Есть строка `DoorBlock#useWithoutItem was reached … locked=true`, а дверь всё равно открылась — значит
  открывает не этот путь (другой мод, контрапция, другой тип двери). Прислать лог, я разберу по строке.
- Нет строки `was reached` вовсе — перехват не привязался, сигнатура метода в вашем рантайме другая.
  Тогда исправлю дескриптор по логу (и, скорее всего, добавлю вторую точку перехвата).
- Есть строка с `locked=false` — замок не виден там, куда вы кликаете (например, разные половины двери
  или другое измерение). Тоже чинится точно.

## Что не подтверждено в игре

- Дескриптор `DoorBlock#useWithoutItem(BlockState, Level, BlockPos, Player, BlockHitResult)` взят из
  javadoc 1.21.1; на вашем рантайме (NeoForge 21.1.265) он в игре ещё не проверялся. `require = 0`
  гарантирует, что при несовпадении игра запустится, а эффект будет как у 370.
- Поведение дверей из других модов: перехват стоит на `DoorBlock`, поэтому дверь, которая
  переопределяет `useWithoutItem` в своём классе, его не увидит.
