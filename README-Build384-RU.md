# Settled Lands — сборка 384 (значения графа двери теперь сохраняются)

Файл мода: `settledlands-0.8.0-build384-door-graph-save.jar`
Версия в игре: `0.8.0-build384-door-graph-save`
Собрано из базы: `settledlands-0.8.0-build383-door-graph-fix.jar`

## Что было не так

Ты написал: «Изменения в графе не сохраняются и в следствии не влияют на дверь». Это не потерянный
пакет и не сломанный хук — я выбрал не те поля ноды. Вот строка из `NpcDialogueGraph.save()` базового
мода, за которую всё и зацепилось:

```java
if (n.type == TIMER)  { v.putInt("TimerInterval", n.timerInterval); v.putBoolean("TimerRepeat", ...); }
if (n.type == RANDOM) { v.putInt("RandomMin", n.randomMin); ... }
```

В 382-й я держал «Кол-во чисел» в `randomMin`, «Скорость» в `timerInterval` и «Закрыта» в
`timerRepeat`. Тип ноды двери — 40, это не TIMER и не RANDOM, поэтому **эти три поля не писались
вообще**. Редактор отправлял на сервер ноду со значениями по умолчанию (1 / 10 / true), сервер это
записывал, и каждое сохранение переписывало дверь как «4 клавиши, 10 секунд, закрыта». Ничего не
падало и ничего не писало в лог — поэтому это и всплыло только из игры.

## Что исправлено

1. **Значения переехали в поля, которые сохраняются для любого типа ноды** — `Node#varValue`
   (число чисел), `Node#varCompare` (скорость), `Node#varOp` (закрыта, 1/0). Это три целых, которые
   сериализатор пишет и читает каждому узлу без проверки типа (они принадлежат узлам «Переменная», а
   строки «Переменной» в инспекторе двери не строятся — они уводятся ещё с 383-й). Соответствие
   записано в `DoorGraph382.FIELD_NOTE` рядом с кодом, который его читает, чтобы это не пришлось
   искать снова.
2. **Нода, записанная сборками 382/383, восстанавливается, а не переписывается пустой.** У такой ноды
   `varValue == 0` — у записанной ноды этого быть не может, число клавиш 4…10. При открытии графа и
   при сохранении её заполняет новый `DoorGraph382.adopt`: значения по умолчанию (6 клавиш, 5 с) и
   **настоящий** замок двери. Поэтому старая дверь открывается с реальными числами, а закрытая дверь
   не отпирается от того, что ты открыл её граф.
3. Больше ничего не менялось: та же нода, те же два ползунка и тумблер, та же карточка, тот же замок
   368-й, тот же пакет `P|key=count:seconds` для панели.

## Что проверить (важно — по шагам)

1. ПКМ жезлом по двери → в графе одна нода «Дверь», ползунки стоят на 6 и 5 (или на том, что ты
   ставил раньше, — при первом открытии старой двери будет 6 / 5 и её настоящее состояние).
2. Поставь, например, **9 клавиш** и **2 с**, тумблер «Закрыта», нажми **Ctrl+S** (или кнопку
   сохранения) → внизу должно появиться «Граф двери сохранён · x y z · Закрыта (только взлом)».
3. Закрой граф и **открой заново** → ползунки на 9 и 2, тумблер «Закрыта». Это и есть проверка того,
   что значения пережили сохранение (до 384-й здесь всегда были 4 / 10 / закрыта).
4. Клик по двери без жезла → панель взлома с **9** клавишами, смена одной клавиши раз в **2 с**.
5. Переключи «Открыта», Ctrl+S, закрой → дверь снова открывается обычным кликом, без панели.
6. Выйди из мира и зайди снова → значения на месте (граф живёт в данных мира).
