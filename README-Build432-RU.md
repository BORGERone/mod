# Settled Lands — Сборка 432 (`0.8.0-build432-deadend-corridors`)

База: `settledlands-0.8.0-build431-create-nbt-support.jar` (`0.8.0-build431-create-nbt-support`), без новых миксинов и без новых внешних API относительно Build 431.

## Что изменено в Build 432

**Все коридоры и ветки «Адского данжа» теперь заканчиваются реальными тупиковыми комнатами (`Тупик 1..4`) вместо плоских стен из незерских кирпичей (`minecraft:nether_bricks`).**

Ранее (в Build 431) в среднем **18.4 выхода на один данж** (из-за столкновений соседних веток, поворотов или упора в `max_radius`) не вмещали комнату или тупик и закрывались плоскими `3×5` заглушками `Seal` из незерака.

### Как это исправлено в `DungeonGenerator427`:

1. **Инвариант зарезервированного тупика (`tryPlaceWithCaps` / `findCapAvoiding`)**:
   - Для каждого открытого выхода (`OpenExit`) поддерживается гарантированно влезающий (без пересечения границ и соседних комнат) зарезервированный тупик (`reservedCap`).
   - Перед размещением новой комнаты/разветвления генератор проверяет:
     - строгий бюджет комнат (`1 + newExits <= slotsRemaining`, чтобы финализация не превышала `max_pieces`),
     - совместимость с зарезервированными тупиками уже открытых соседних веток (если новая комната перекрывает чужой резерв, соседняя ветка предварительно перерезервируется на другой тупик; если места для тупика не остаётся — комната отклоняется, не запирая соседа в стену),
     - наличие валидных тупиков для каждого нового выхода добавляемой комнаты.
2. **Автоматический мост-коридор для тесных многовыходных перекрёстков (`shortestBridgeCorridors`)**:
   - Выявлена геометрия узких 3-выходных перекрёстков (например `к/а/п Перекрёсток 1` `9×11×9`), у которых боковые и передний тупики шириной `13..19` блоков пересекаются углами прямо за перекрёстком.
   - При конфликте углов генератор автоматически удлиняет конфликтующий выход коротким узким коридором (`Коридор`) с тупиком на конце вместо отказа или заглушки.
3. **Равномерное распределение всех тупиков на закрытии и поддержка обоих режимов**:
   - Инвариант работает как в биомном режиме (`auto->biomes(к->а+п)` — каждый биом закрывается строго своими тупиками `к/а/п Тупик 1..4`), так и в плоском режиме (`all`, `tag:*`, `prefix:*`, пользовательские папки).
   - На финализации веток вместо однообразного компактного тупика случайным образом выбираются любые допустимые тупики темы (с безотказным fallback на гарантированный `reservedCap`), благодаря чему в генерации равномерно встречаются все 12 вариантов (`к/а/п Тупик 1..4`).
   - Входная тыльная арка стартового зала (`старт.entrance`, `seal_start_entrance=true`) сохранена без изменений, чтобы за спиной игрока при спавне не было пустоты; при отсутствии тупиков в кастомной папке (`deadEnds.isEmpty()`) работает мягкий fallback.
