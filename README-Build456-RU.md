## Что изменено в Build 456

### 1. Нода «Значение переменной» — чистый нейминг и полный набор портов
- **Убран брендинг `UE5`**: во всех строках интерфейса (`ru_ru.json` / `en_us.json`), описаниях, тултипах, контекстных меню и комментариях кода нода теперь называется **«Значение переменной»** (`Variable Value`).
- **Оранжевые порты (вход и выход данных)**:
  - Слева (`y = 74`) добавлен **оранжевый входной пин**, принимающий динамическое значение от другой ноды `Значение переменной` (по цепочке, без рекурсивных циклов).
  - Справа (`y = 74`) сохранён **оранжевый выходной пин** для передачи значения в `IF`, `VARIABLE`, `Pursuit` или в следующую ноду `Значение переменной`.
  - В инспекторе `VarDataInspector453` отображается статус входящего оранжевого провода и кнопка мгновенного отсоединения, а также поддерживаются перегибы (`NpcWirePoints321`), ховер/резка (`WireHover453`) и всплывающие подсказки (`GraphTooltips448`).
- **Синий пин сущности (цели/игрока)**:
  - Внизу карточки (`y = 92`) добавлен **синий входной пин** для привязки ноды-цели (`CHECK`, `RADIUS`, `Pursuit`), задающей носителя локальной переменной.
  - Синяя и оранжевая привязки хранятся независимо (`entityInput453` / `ValuePinInput` и `varInputNode`), сохраняются в NBT (`VarGraphIoMixin453`) и в буфере обмена (`NpcGraphClipboard318`).
- **Белые порты выполнения (поток)**:
  - Ноду «Значение переменной» можно **включать в обычную белую цепочку диалога/триггера** (`next` / `falseNext` / `randomBranches`) через правый и левый белые порты (`y = 50`) во всех 6 граф-редакторах (включая автоподключение из контекстного меню).
  - При срабатывании по белому проводу нода синхронно вычисляет/перезаписывает целевую переменную (с разрешением `NPC` / игрока-носителя через синий пин, локального `UUID`-ключа `Pursuit` и опциональным пробросом `VARIABLE -> Значение переменной`) и передаёт управление дальше по цепочке, не мешая ленивому чтению через оранжевые провода.

### 2. Переключатель формы зоны «Круг / Квадрат» для «В радиусе» и «Цель»
- **Режим «Квадрат» (Чебышёвский бокс, 3D куб)** добавлен в инспектор и на карточки нод **`В радиусе` (`CHECK`, тип 5)** и **`Цель` (`RADIUS`, тип 15)**:
  - По умолчанию сохраняется классический **«Круг»** (сфера `dx² + dy² + dz² ≤ r²`).
  - В режиме **«Квадрат»** проверка идёт по каждой оси независимо: `|dx| ≤ r && |dy| ≤ r && |dz| ≤ r` (включая точные грани и углы куба `[x ± r, y ± r, z ± r]`).
- **Охват всех путей проверки и визуализации**:
  - **NPC-диалоги, условия и радиусные вложения** (`GuideDialogue`: `checkProximityCondition`, `findCheckTarget`, `initiatorExecutesWithRadiusGate`, `expandRadiusAttachments`),
  - **Триггерные блоки / двери / сундуки / спавнеры** (`BlockTrigger351`, `NpcRadiusZone320`),
  - **Подсветка границ частицами** (`RadiusPass354`): в режиме **«Квадрат»** вместо кругового кольца рисуется контур квадратного/кубического периметра по 4 углам (от центра блока `+0.5` для блоков).
- **Интерфейс, сохранение и буфер обмена**:
  - Кнопка переключателя **«Форма зоны: Круг / Квадрат»** под строкой «Видимость» мгновенно сохраняет состояние на сервер (`save()`) для перерисовки частиц.
  - На карточке в правом верхнем углу отображается компактный бейдж (`○ Круг` / `□ Квадрат`) и подсказки в инспекторе (`GraphTooltips448`).
  - Флаг `SquareZone456` сохраняется в NBT-графе (`VarGraphIoMixin453`), при дублировании нод (`RadiusZoneNodeMixin456`) и в текстовом буфере обмена (`NpcGraphClipboard318`, попутно исправлено копирование/вставка нод `RADIUS` типа `15`).
