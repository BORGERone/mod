# Приветствие для начала работы над модом SettledLands

Привет! Я хочу начать редактирование своего мода SettledLands для Minecraft 1.21.1 / NeoForge 21.1.253.

## Что я хочу сделать

Я разрабатываю мод с NPC, у которых есть сложная система диалогов, граф поведения, профессии, анимации и AI. Текущий билд — Build 272, который добавляет единую ноду преследования с dropdown, полем ввода и тумблером.

Мне нужно, чтобы ты помогал мне:
- Добавлять новые функции в мод
- Исправлять баги
- Оптимизировать код
- Собирать и тестировать билды

## Правила работы

### 1. Порядок чтения документации
Перед любой работой читай в этом порядке:
- `START-HERE-RU.md` — точка входа
- `HANDOFF-NEXT-SESSION-RU.md` — передача контекста
- `AI-GUIDE-SettledLands.md` — технические детали и уроки
- `SESSION-STATE.md` — текущее состояние проекта

### 2. Дисциплина сборки
- **Никогда не выдавай билд без прохождения gates:**
  - `validate_jar.py` — структура JAR
  - `jvm_verify.py` — JVM верификация
  - `check_mixin_class.py` — проверка mixin классов
  - `verify_jar.py` — полная верификация
- Всегда озвучивай точный diff (сколько записей изменено/добавлено/удалено)
- Обновляй **все** метаданные в `neoforge.mods.toml`: version, description, displayName
- Создавай SHA256SUMS файл для каждого билда

### 3. Стиль общения
- **Коротко, по делу, без оправданий**
- Формат ответа: что случилось → почему → что сделано → что проверить → ссылка на JAR
- Ошибку признавай сразу и конкретно
- **Не показывай SHA и размеры файлов** (я это вижу сам)
- **Ссылка на JAR — в самом конце сообщения**
- Перед ссылкой — только список изменений
- **Не учи меня устанавливать мод** (я знаю как)
- **Проси latest.log только при реальной проблеме**, не напрягай лишний раз

### 4. Раздача билда
- В каждом ответе, где упоминается собранный JAR, **ссылка должна присутствовать**
- Порядок: JAR первым, Source ZIP вторым
- Ссылки оформляй **markdown-ссылками** (кликабельными)
- Ссылки — отдельным блоком в конце ответа
- **Файлы на Google Drive должны быть публичными** (make_public)

### 5. Что нельзя делать
- **Не просить видео** — я не буду его записывать
- **Не просить SHA установленного JAR** — я отказываюсь его предоставлять
- **Не включать Build 263 CUTSCENE fade** — это известная проблема, не трогай её
- **Не предлагать Build 269/270** — они отозваны
- **Не править `Code` существующих классов вручную** — используй только classedit.py/smt.py
- **Не делать speculative patches** — сначала диагностируй, потом исправляй

### 6. Оптимизация
- Ноль лишней работы в per-frame/per-tick путях
- Никаких `AABB` больше ~1e5 (используй `level.getAllEntities()`)
- Не плоди классы и лишние вызовы
- Не тащи `System.out` в горячие пути
- Не "улучшай" попутно ничего, о чём я не просил (правило PROPOSE-ONLY)

### 7. Тестирование
- Gates — это **не игровой запуск**
- После сборки я сам тестирую на копии мира
- Если что-то не работает — я пришлю latest.log
- Не утверждай, что "всё работает" без реального теста в игре

### 8. Git и версионирование
- Работай только в ветке `arena/3069fd2a-mod`
- Коммить изменения с понятными сообщениями
- Пушь в origin после каждого значимого изменения
- Создавай PR когда работа завершена

### 9. Загрузка артефактов
- JAR и Source ZIP загружай на Google Drive
- Коммить JAR в git (для истории)
- Делай файлы публичными на Drive (make_public)
- Давай прямые ссылки на скачивание

### 10. Уроки из прошлых ошибок
- **Build 272:** Всегда обновляй description в neoforge.mods.toml, иначе Night Config парсер упадёт
- **Build 267-268:** Mixin API stubs должны точно сохранять RetentionPolicy (RUNTIME vs CLASS)
- **Build 257-258:** Проверяй точные сигнатуры методов (boolean vs void)
- **Build 233:** Порядок сборки пула — все `cp.utf8()` должны быть добавлены ДО `cp.dump()`
- **Build 231:** `@Mixin.value` — это массив, кодируй как `5b 0001 63 <descriptor>`
- **Build 230:** Не вставляй байты в `Code` вручную — используй classedit.py/smt.py
