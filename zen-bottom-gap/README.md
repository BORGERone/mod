# Отступ снизу на выбранных сайтах (Zen Browser)

Задача: на некоторых сайтах в конце страницы не хватает воздуха (по умолчанию — 26px). Zen — Firefox-форк,
поэтому доступны те же механизмы: `userContent.css`, WebExtension, userscript.

**Готовое:**

| Файл | Что это |
|---|---|
| `extension/` | **основной вариант**: расширение с тумблером «на этом сайте» в тулбаре |
| `userContent.css` | то же без аддонов — список доменов в файле профиля |
| `bottom-gap.user.js` | то же юзерскриптом (`@match` на каждый сайт) |
| `userChrome.css` | отступ на уровне браузера — глобально, зато единственный способ, который реально поднимает страницу над кромкой окна |

---

## Что выбрать

| Способ | Как включается сайт | Добавить новый сайт | Минусы |
|---|---|---|---|
| **Расширение** (`extension/`) ← для «определённых сайтов» | клик по иконке → чекбокс | клик, 1 секунда, без перезагрузки | ставится один раз (временное — до перезапуска, постоянно — с подписью) |
| **Stylus** | правый клик по иконке → «Write style for site» | пару кликов, есть готовый UI | ещё один аддон ради 3 строк CSS |
| **uBlock Origin** | строка в «My filters» на домен | править фильтры, перезагрузить страницу | `:style()` требует явного хоста (глобально не работает), ворох фильтров не место для вёрстки |
| **`userContent.css`** | блок `@-moz-document domain(...)` | правка файла + **перезапуск Zen** | нет UI, каждое изменение = рестарт |
| **Userscript** | строка `@match` | правка шапки скрипта | лишний слой, на строгом CSP инъекция `<style>` иногда отваливается |

Если сайтов станет много и они начнут меняться — `userContent.css` начнёт бесить именно
перезапуском. Расширение в этом смысле единственный вариант с нормальным циклом
«увидел сайт → включил → сразу видно».

Обратный случай: если нужно «20px везде, кроме трёх сайтов» — выгоднее глобальное правило
(`userContent.css` без доменов) плюс блок-исключение, чем список из сотни доменов.

## Вариант 1 — расширение (рекомендую)

Файлы: `extension/manifest.json`, `gap.js`, `popup.html`, `popup.js`, `extension/icons/*.png`.
Manifest V3, разрешения только `storage` + `activeTab`, CSS ставится инлайново через CSSOM —
без фоновых скриптов. Иконки (16/32/48/96/128) генерируются `make-icons.py` — код рисует их
сам, внешних ассетов нет.

Три независимых режима на каждый сайт:

| Чекбокс | Что делает | Что видно на экране |
|---|---|---|
| **добавлять на этом сайте** | `padding-bottom` на `<html>` | ничего, если у страницы однотонный фон (см. ниже) |
| **покрасить полосу** | в конец `<body>` вставляется распорный блок нужной высоты с полупрозрачной плашкой | страница явно заканчивается на 26px выше — работает на любом сайте |
| **поднять нижние панели** | ищет `position: fixed` у нижней кромки и поднимает их (`bottom += px`) | плеер/док-бар больше не касается низа окна |

Зачем нужна «полоса»: `padding` на `<html>` добавляет место, но это место закрашивается
фоном самой страницы, поэтому на однотонных сайтах выглядит как «страница просто
закончилась». Плашка делает отступ видимым. Когда она включена, `padding` не ставится —
иначе отступ был бы двойным.

Режим «панели» — ответ на «плеер как был внизу, так и остался»: `padding` на `<html>` не может
сдвинуть фиксированный элемент, он считается от вьюпорта. Подъём делается по факту
`position: fixed` + `bottom !== auto` + приклеен к нижней кромке (±4px); полноэкранные
оверлеи (модалки, лайтбоксы) и `sticky`-хедеры не трогаются.

Когда расширение пересканирует страницу:

| Триггер | Что ловит |
|---|---|
| `MutationObserver` (childList + `class`/`style`/`hidden`) | панель добавили в DOM **или** она уже была и стала видимой — так ведёт себя плеер Newgrounds при старте трека |
| `transitionend` / `animationend` | панель выехала анимацией и «встала» только к концу |
| тик раз в 2 с | SPA, которые показывают панель вообще без мутаций в `body` |
| первые 0/0.4/1.2/3 с после загрузки | вёрстка «доезжает» после DOMContentLoaded |

Проходы ограничены одним сканом в 350 мс и не выполняются, когда вкладка скрыта — иначе
на тяжёлой странице это превратилось бы в постоянный layout thrash.

Установка:

1. `about:debugging#/runtime/this-firefox` → **Загрузить временное дополнение**.
2. Выбрать `extension/manifest.json` (иконка появится на панели; своей иконки нет — будет
   стандартная «паззл», это нормально).
3. Открыть нужный сайт → клик по иконке → чекбокс **«добавлять на этом сайте»** → при
   желании поменять 20 на другое число.
4. Если внизу висит фиксированный плеер/док — включить второй чекбокс
   **«поднять нижние панели»**. Попап напишет, сколько панелей реально поднято
   («Поднято панелей: 1») или что таких не нашлось.

Как работает:

- ключ в `storage.local` — `hostname` (без пути и порта), значение — отступ в px;
- content script стоит на всех http/https, но стиль ставит только если хост есть в списке;
- попап пишет в storage, страница ловит `storage.onChanged` — отступ появляется/убирается
  **сразу, без F5**;
- вкладки, открытые до установки аддона, скрипта не имеют — попап честно скажет
  «перезагрузите вкладку».

### Настройки не выживают перезапуск

Это свойство временных аддонов: при остановке браузера они выгружаются, и «any data in
local or sync storage is lost». Быстрое лекарство, если хочется остаться на временной
загрузке, — два префа:

```
extensions.webextensions.keepStorageOnUninstall = true
extensions.webextensions.keepUuidOnUninstall   = true
```

После этого `storage.local` переживает перезапуск, и список сайтов никуда не девается.
Постоянная установка (раздел ниже) решает вопрос надёжнее — данные живут в профиле как
у любого обычного расширения.

Временный аддон пропадёт при перезапуске Zen — см. раздел
[«Поставить навсегда»](#поставить-навсегда) ниже.

### Поставить навсегда

Три рабочих пути. Zen, в отличие от ванильного Firefox, собран без `MOZ_REQUIRE_SIGNING`,
поэтому в нём (и только в нём) работает и первый вариант.

**1. Выключить проверку подписи — 30 секунд, без аккаунтов**

1. `about:config` → `xpinstall.signatures.required` = `false`
2. `about:addons` → шестерёнка → **«Установить дополнение из файла…»** → выбрать
   `dist/bottom-gap-<версия>.xpi`
3. Перезапустить Zen — аддон остаётся на месте и обновляется как обычный.

Минус: флаг глобальный, после него в браузер можно молча поставить любой неподписанный
`.xpi` (в том числе присланный «доброжелателем»). Для личной машины приемлемо, для чужой —
нет. В `about:debugging` идти уже не нужно: это полноценная установка.

**2. Положить в профиль — переживает обновления Zen**

Файл кладётся прямо в профиль, браузер подхватывает его при старте (так это делает
`zen-ext` и подобные установщики):

```bash
# папка профиля: about:support → «Открыть папку»
cp dist/bottom-gap-2.4.0.xpi \
   "<профиль>/extensions/bottom-gap-20@local.xpi"
```

Имя файла обязано совпадать с `gecko.id` из манифеста. Плюс в `<профиль>/user.js`:

```js
user_pref("xpinstall.signatures.required", false);
user_pref("extensions.autoDisableScopes", 14);   // не отключать аддон из папки профиля
user_pref("extensions.startupScanScopes", 1);    // сканировать папку при каждом старте
```

Обновление версии = заменить файл. Ничего никуда не «устанавливается», но при этом флаг
подписей всё равно выключен — цена та же, что в варианте 1.

**3. Подписать в AMO (unlisted) — единственный путь с включённой проверкой подписей**

1. `addons.mozilla.org/developers` → войти (аккаунт Mozilla, бесплатно).
2. **Submit a new add-on** → **On your own** (self-distribution, аддон нигде не публикуется).
3. Загрузить `dist/bottom-gap-<версия>.xpi` → автоматическая валидация, подпись через
   пару минут.
4. Скачать подписанный `.xpi` → `about:addons` → шестерёнка → «Установить дополнение из
   файла…». Ставится как обычное расширение, `xpinstall.signatures.required` остаётся `true`.

Дальше: правка кода → поднять `version` в `manifest.json` → `./build.sh` → загрузить новую
версию на AMO → поставить новый `.xpi` (AMO не подписывает одну и ту же версию дважды).
Старые подписанные версии можно не удалять из аккаунта.

Чего сделать нельзя: подписать за вас — это ваш аккаунт. Файл для загрузки лежит в `dist/`.

Стенд лежит рядом: `node test/gap.test.mjs` (Node + заглушки DOM, браузер не нужен).
30 проверок: подъём fixed-панели, появление панели уже после загрузки,
обновление значения без перезапуска, возврат чужого инлайнового `bottom`, отсев
оверлеев/`sticky`/`bottom: auto`, видимая плашка без двойного отступа, снятие всех
следов при выключении сайта.

Где доработать под себя:

- `gap.js` → `location.hostname`: сейчас хост сравнивается точно, поэтому `www.site.com`
  и `site.com` — разные записи. Нужны поддомены — замените на поиск по суффиксу
  (`for` по `host.split('.')`), см. комментарий в файле;
- размер по умолчанию — `DEFAULT_PX = 26` в `popup.js` (+ `value="26"` в `popup.html`),
  диапазон 1–300 px в `clampPx()`; у каждого сайта значение своё и хранится в `gaps`.

## Вариант 2 — `userContent.css` (без аддонов)

1. `about:support` → «Открыть папку» профиля → создать `chrome/` → положить
   `userContent.css`.
2. `about:config` → `toolkit.legacyUserProfileCustomizations.stylesheets` = `true`.
3. Перезапустить Zen.

Формат — блок на сайт (файл уже размечен, копируйте блок):

```css
@-moz-document domain("example.com") {
  html {
    box-sizing: content-box !important;
    padding-bottom: 20px !important;
  }
}
```

`domain("site.com")` покрывает и поддомены (`www.site.com`). Новый сайт → правка файла →
**перезапуск браузера** (`F5` не перечитывает `userContent.css`).

Плюс варианта: user-origin стили перебивают даже авторские `!important` и инлайновые
стили, не зависят от CSP и не видны сайту как активность.

## Вариант 3 — userscript

`bottom-gap.user.js` → Violentmonkey/Tampermonkey → «Создать скрипт» → вставить.
Сайт добавляется строкой в шапке:

```js
// @match        *://site.com/*
// @match        *://*.site.com/*
```

У менеджера есть переключатель «включён на этом сайте» — то есть UI почти как у варианта 1,
но с зависимостью в виде аддона.

## Почему отступ «ничего не делает»

Потому что внутри страницы нельзя сделать зазор на кромке окна. Веб-контент всегда
занимает весь вьюпорт, и всё «пустое», что мы оставляем в документе, закрашивается фоном
самой страницы: фон корневого элемента распространяется на всю канву, включая padding.
Отсюда два следствия:

- 20px в конце документа есть, но они того же цвета, что страница, — глазу не за что
  зацепиться;
- на сайтах-приложениях (почта, редакторы, соцсети), где скроллится не документ, а
  внутренний `div`, места не появляется вовсе.

Режим «покрасить полосу» — попытка сделать это заметным: он рисует плашку вместо
невидимого паддинга. А настоящий зазор (когда видно фон браузера) возможен только на
уровне хрома — `userChrome.css`, см. последний раздел. Он ещё и плееры поднимает сам,
потому что область страницы становится ниже.

## Почему плеер внизу не сдвинулся от отступа

`position: fixed` позиционируется относительно **вьюпорта**, а не документа. Сколько бы
`padding-bottom` ни было у `<html>`, фиксированный бар останется на `bottom: 0` — то есть
ровно у нижней кромки окна. Именно поэтому в расширении появился второй режим: он находит
такие элементы и добавляет им сам отступ.

Чего этот режим не умеет: бары, приклеенные не через `bottom` (а, скажем, через `transform`),
бары внутри iframe и `sticky`-элементы (они живут в потоке документа — им хватает первого
режима). Для совсем упрямого сайта остаётся точечное правило под его селектор.

## Почему именно `html` + `padding`

- `padding` на **корневом** элементе прибавляется к высоте документа: 20px появляются в
  конце страницы, существующая вёрстка не сдвигается (и не «прыгает» при позднем
  применении — поэтому расширение может ставить стиль хоть через 100 мс).
- `margin-bottom` на `body` часто схлопывается; `padding-bottom` на `body` ломает
  раскладки с `height: 100%`.
- `box-sizing: content-box !important` обязателен: почти все CSS-ресеты ставят
  `* { box-sizing: border-box }` и на `<html>` тоже, а при `border-box` + `html { height: 100% }`
  padding «съедается» высотой и его не видно.

## Грабли

1. **Пустое место красится фоном страницы.** Фон корневого элемента распространяется на
   канву, поэтому «воздух» в конце документа выглядит как продолжение фона. Именно поэтому
   появился режим «покрасить полосу».
2. **Сайты-приложения** (почта, редакторы, соцсети), где скроллится не документ, а
   внутренний `div` с `overflow: auto`: padding на `<html>` там ничего не даст, нужен
   точечный селектор под конкретный сайт.
3. **`100vh`-секции**: документ станет выше экрана ровно на величину отступа — появится
   микроскролл. Ожидаемо и безвредно.
4. **iframe**: `all_frames: false` — отступ только у верхнего документа, внутри фреймов не
   появляется (обычно это и нужно).

## Готовый `userChrome.css` (уровень браузера)

Файл `userChrome.css` в этом каталоге: кладётся в `<профиль>/chrome/`, включает
`toolkit.legacyUserProfileCustomizations.stylesheets = true`, перезапуск Zen.

```css
#tabbrowser-tabpanels { padding-bottom: 20px !important; }
```

Работает глобально (все вкладки, включая `about:` и страницы расширений), по списку
сайтов не разделяется — CSS хрома про сайт в вкладке ничего не знает. Зато это
единственный вариант, который действительно отодвигает страницу от кромки окна, и он же
автоматически поднимает фиксированные плееры.

## Если имелся в виду зазор вокруг страницы, а не в конце неё

То есть контент не должен прилипать к нижней границе окна. Это хром браузера, а не сайт —
`userChrome.css` (та же папка `chrome/`, тот же флаг):

```css
#tabbrowser-tabpanels { padding-bottom: 20px !important; }
```

Селектор внутреннего контейнера в Zen меняется от версии к версии — проверяйте через
Browser Toolbox (`Ctrl+Alt+Shift+I`). Вот это как раз территория «модов Zen»: моды — это CSS
хрома, до содержимого страниц они не достают.
